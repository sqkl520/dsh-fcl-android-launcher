# 版本说明（面向用户）

> 每个版本一段，写清**「这一版对你有什么变化」**。GitHub Release 的正文就取自这里。
> 最新版本在最上面。
>
> **版本号只有一个真源**：仓库根 `gradle.properties` 的 `dshVersion`。
> 本文件里最新的那个版本号必须与它一致。
>
> 写法：**一个 `##` 一个版本 → 一句话摘要 → 分类小节 → 升级须知**。
> 分类标题一律用 Keep a Changelog 的英文原名：`Added` / `Changed` / `Deprecated` /
> `Removed` / `Fixed` / `Security`，加两个补充：`Known limitations` / `Upgrade notes`。
> 硬规则：同一版本 `Fixed` 只出现一次（多件事用列表分条）；标题里不放括号和技术名词；
> 写"用户感受到什么"而不是"改了哪行"；没解决的事写进 `Known limitations`，不要藏着；
> `Upgrade notes` 里只写"装之前要知道的"，测试步骤和单测数字属于技术细节，放进对应条目内部。

> ⚠️ **历史段落的已知失真**：早期版本（fix1 ~ fix7）的"升级须知"里写的"首次启动会重新解压
> 脚本（几 MB）"，体积实测只有 **约 34 KB**（`scripts` 子目录合计 34 013 B），且对**已装过**
> 的用户并不会自动发生（fix10 起才在启动时真正比对脚本版本）。这些段保留原文作为历史记录，
> **以最新一段为准**；不要再据此估算升级耗时。

## 0.1.6-SNAPSHOT-fix40

> **修掉了编辑配置时 App 崩溃，以及配置文件改不进去的两个问题。**

  `Files.move(REPLACE_EXISTING, ATOMIC_MOVE)`。`R48FileEditWriteTest` 十条钉住四条不变量：
  写前留 `.bak`、原子替换、失败清 `.tmp`、UTF-8 往返。

### Upgrade notes

## 0.1.6-SNAPSHOT-fix33

> **在 dsh 界面里发消息不会再报「会话已被占用」了。**

### Fixed

- **新建的会话也能正常发消息。** 此前无论用哪个会话，第一条消息就报
  `session "…" is already owned by an active write handle`，换成全新的会话也一样。

  dsh 的会话锁在 flock 成功之后还要校验 `handle.stat()` 与 `stat(path)` 的 `ino`/`dev` 一致，
  3 次不匹配就抛 `SessionAlreadyOwnedError`。在 proot 虚拟化的文件系统上这次自校验恒失败。
  修法是启动时用 `NODE_OPTIONS=--require` 预载一个投影脚本，让两处取到一致的值。

  ⚠️ 副作用：这个投影会让会话锁的异常检测永久失效——真正被别的进程占用时也检测不出来了。

### Upgrade notes

- **直接覆盖安装**（fix32 → fix33 无需卸载）。

## 0.1.6-SNAPSHOT-fix26

> **你添加的模型提供方不会再消失了。** 此前应用重启一次，自己配的模型服务就被抹掉。

### Fixed

- **自定义模型服务重启后还在。** 此前启动器每次启动都会重写实例目录里的那份配置文件，而它正是
  dsh 读取自定义模型服务的地方，于是你按 dsh 文档配的 provider 下次启动就被抹掉。现在启动器只
  维护自己那两条，其余原样保留。

  `writeLauncherPatchOverlay` 原为整份覆盖，现改为合并：按 id 认领 `client-hmr` 与
  `launcher-assets`，其余条目保留并排在其后（dsh 的 patch 语义是后者覆盖前者）。
  `R45LauncherPatchMergeTest` 共 9 条，其中一条断言生产调用点确实调用了合并函数——
  改回覆盖会让它变红。单测 1060/1060、脚本自检 33/33。

  真机实测（KKG-AN00 / Android 10）：往 `launcher.patch.yml` 写入一个 `mygateway` provider，
  强杀 App 再启动，该条目仍在，且启动器自己的两条也都在——三者共存。

### Upgrade notes

- **直接覆盖安装**（fix25 → fix26 无需卸载）。

## 0.1.6-SNAPSHOT-fix22

> **复制访问链接之后，不再反复弹同一个框。** 外部浏览器打开界面时也不必每次重下前端文件了。

### Fixed

- **复制链接成功后不再把同一个框摆回来。** 此前点「复制链接」、链接已经进了剪贴板，两秒后界面又
  弹出「仍要继续 / 复制链接 / 用外部浏览器打开」——问的是你刚做过的选择。现在复制**成功**后停在
  一块「链接已复制」的面板上，带重试 / 日志 / 停止 / 关闭四个出口；从浏览器切回 App 也不会再被问。
- **没复制成功、或你取消了确认框时，行为不变**：仍回到门禁框让你重新决定。只有"链接确实进了
  剪贴板"这一种情况才走新路径。
- **外部浏览器打开界面时，不再每次重新下载前端文件。** dsh 自己的前端服务不发缓存头，所以此前
  每次打开都要把约 2 MB 的前端资源重下一遍。现在这些文件带上了长期缓存标记，第二次打开基本不再下载。
- **修完后的实际下载量：首次约 5 MB，之后基本不用重下。** 此前文档写"首屏 545 KB"是错的——那
  只量了前端主包，漏掉了 58 个插件包（它们不是按需加载，首屏整批注入，gzip 后约 4.4 MB）。
  这 5 MB 里，插件包和前端资源现在都带缓存，只有第一次或版本变化时才重新下载。
- **dsh 的热更新轮询从每 0.5 秒拉长到每 5 秒。** 只省持续的后台 CPU 开销，不改变打开速度。
  没有整个关掉它——关掉后"装完插件、页面不刷新就出现"这个能力会静默失效，那比慢一点更糟。

  单测 513/513、脚本自检 28/28。本轮新增的测试专门盯"调用点真的接上了"，
  并做了 5 次变异验证（把实现改回旧行为，测试必须变红）。

### Known limitations

- **退出再进界面仍会提示一次 WebView 过旧。** 那个"已复制"标记只活在当前页面里，没有存盘——
  存下来会让这台设备永远不再提示，而那是你知道"内嵌界面会崩"的唯一机会。
- **开着确认框时按 Home 再回来，门禁框仍会被重摆一次。**

### Upgrade notes

- **直接覆盖安装**（fix21 → fix22 无需卸载）。
- **脚本已更新（11 → 12）**：升级后**首次启动会走一次准备页**重新解压脚本（秒级，不动 rootfs 与
  实例数据），之后不再重复。带 `--patch` 启动若在就绪前退出，脚本会自动去掉 `--patch` 重试一次
  ——优化项永远不该成为"起不来"的原因。

## 0.1.6-SNAPSHOT-fix21

> **先更正上一版说错的三件事**，再给"空目录"这个踩了三次的坑加上自动告警。

### Changed

- **上一版说错的三件事，这里更正**：
  - **「前端包不压缩」是错的。** dsh 的前端包**是** gzip 压缩的（压缩级别 1，超过 1 KB 才压）。
    此前把未压缩体积当成了实际传输量。
  - **「WebView 114 解释了界面慢」是错的。** 你是在**外部浏览器**里操作，那个客户端根本不用系统的
    WebView。这条只解释"App 内嵌界面在旧机型上可能崩"，与"外部浏览器慢"无关——两件事写混了。
  - **「1.35 MB 每次重传」不是实际传输量。** 那是未压缩体积。"每次刷新要重新下发一遍"这个结论
    本身仍然成立（前端资源确实没有缓存头），但数字比这个小得多。

### Fixed

- **启动时会检查「启动目录」里有没有子目录**，没有就在日志里写一行 `WARN home-has-no-subdir`。
  这个坑连续踩了三次（`/root` 空 → `workspace` 空 → 自定义目录不存在），每次症状都一样：对话框
  打开是空框、**没有任何报错**。以后把日志发过来，能直接看出是不是这个原因。
- **设置页「启动目录」的说明补全**：改完**重启后生效**；只有 `workspace` 是对的，`node_modules`
  和 `home` 都不要选（`home` 里放着你的 API Key）。
- **「打开」按钮的行为写清楚了**：**没点任何目录直接按「打开」，选中的是当前那一层目录本身**
  （会建出一个名字像 `inst-1792…` 的工作区）。要选 `workspace`，**先点它，再按「打开」**。

### Known limitations

- **两种症状其实是两种病，这一版只解决了第一种**：
  - **空框、没有转圈** = 列表成功返回但条目是 0，即"启动目录是空的" —— 本版已修（加了告警）；
  - **右下角一直「加载中…」** = 请求发出去了但超过 0.3 秒没回来，是另一条路径，与"目录是不是空的"
    无关。**本版没有修这条**。若你仍看到「加载中…」，请把日志发出来（看有没有
    `home-has-no-subdir` 即可区分）。
- **外部浏览器的「慢」本版未解决。** 原因是 dsh 的静态资源没有缓存头，属于上游行为。

### Upgrade notes

- **直接覆盖安装**（fix20 → fix21 无需卸载）。

## 0.1.5-SNAPSHOT

> 本版把**界面皮肤对齐到 FCL 原版**、**给任务区补上"结果"**、并**把 API Key 完全交给 dsh**。

### Added

- **任务区现在会说"结果"**：以前只显示"正在进行"，取消或失败之后那一行**瞬间消失**，
  用户看不到发生了什么。现在完成 / 失败 / 已取消都会留在列表里（保留最近 20 条），
  失败会带上原因；取消与停止也换成了两张不同的图标（原来长得一样）。
- **首次进界面时会提示去哪填 API Key** —— 只提示一次，之后不再打扰。
- **新增繁体中文**。

### Changed

- **API Key 完全由 dsh 自己管**：启动器不再保存、不再注入、也不再在启动前检查。
  - 表现上的变化：**没配 Key 也能启动**（以前会弹一个"尚未配置 API Key"的框挡住），
    起不来的是对话而不是整个实例。填 Key 的位置在 **dsh 界面里 → 设置 → 模型**。
  - **为什么必须这么改**：dsh 把"从启动环境继承来的 Key"视为最高优先级且**只读**，
    一旦启动器注进去，你在 dsh 的模型页里改 Key 会**直接被拒绝**（报错），
    等于在 App 里无论如何都改不掉。所以这不是取舍，是必须去掉。
- **实例详情里的"模型"设置行去掉了**：查证后确认那一项**从来没生效过** ——
  它对应的是一个并不被 dsh 读取的环境变量（同名常量在 dsh 里是另一个东西）。
  模型请到 **dsh 界面 → 设置 → 模型** 里选。
- **界面皮肤按 FCL 原版逐个对齐**（这一项看起来琐碎，但"塑料感"基本都来自它）：
  - **实例卡片在暗色下不再发白**（`auto_tint` 挂在错误的控件类上，一直静默失效）；
  - **图标不再全是默认黑色**（着色只对背景生效，以前挂在 `src` 上等于没上色）；
  - **切换亮暗主题后，已显示的行不再停在旧配色上**；
  - 日志页不再用自创的深色终端配色，改用与主题配套的一套，亮暗各一份；
  - 一票尺寸/留白/层级的对齐：页面左右留白、右面板内边距与标题字号、设置行的点击反馈、
    开关行高、组标题弱化、版本行的安装按钮改图标、任务区与其它列表统一。
- **语言选项从 12 项精简为 4 项**：跟随系统 / English / 简体中文 / **繁體中文**。
  其余几种既没有对应的翻译文件、也没有人校对，选进去只会得到一份半英半中的界面 ——
  比"没有这个选项"更糟。你原来选的如果是繁体（香港或台湾），升级后仍是繁体。
- **安装过程中显示的文字以前不会跟着语言变**（那段文字来自运行环境里的脚本，
  没有多语言机制）。现在脚本只报"阶段标识"，由 App 翻译 —— 英文界面下安装进度也是英文。
  运行环境准备、自检报告、通知栏、以及"停止原因"这些也一并跟着语言走了。

### Fixed

- **取消安装后"安装中"再也不消失**（要重启 App 才恢复）：取消时没有发出"结束"信号，
  界面永远等不到。现在取消有明确终态，且不会再闪一下"安装失败"。
- **"停止"可能停掉另一个实例**：任务行的停止动作没校验归属，从渲染到点击之间状态一变就停错。
- **运行时准备失败几乎看不到原因**（只在极短的竞态窗口里闪一帧）—— 现在会留在任务区。
- **安装失败记录无限增长**（内存缓慢泄漏）—— 失败后也做一次清理，原因不会丢。
- **安装失败时会告诉你真正的原因了**：以前不管什么原因，界面上只有一句
  「安装失败（详见日志）」。原因是**认不出新版本 npm 的报错格式**
  （npm 10 把错误行前缀从 `npm ERR!` 改成了 `npm error`），于是一条错误都没被收集到。
  现在会明确告诉你是什么问题、该怎么办 —— 例如「DNS 解析失败：当前网络无法解析域名，
  请换个网络或稍后重试」「网络超时，已下载的包有缓存不会从头再来」。
- **日志页滑到最底部会瞬间弹回最上面**（和"自动滚动"开关无关）：正文区域开了"可长按选中"
  （Android 的机制：每次刷新都会把光标位置重置到第 0 个字符，系统随后会把第 0 行滚回可见区）。
  代价是正文不能再长按选中 —— 「复制全部」按钮还在，功能没丢。
- **实例列表长按卡片会"破开"、露出底下的左滑菜单**：左滑菜单已**删除**；
  里面的两个动作（设置 / 删除）在「更多」里都有。
- **「更多」弹出菜单的风格与整个界面割裂**：换成了与设置页同款的 FCL 风格列表对话框。
- **"三个点"紧贴着"启动/重试"按钮、容易误触**：把它的可点区域从 20dp 撑到 40dp
  （与其它图标按钮一致），两个按钮的间距与垂直对齐也理了一遍。
- **装之前会检查磁盘空间**：以前只有"解压运行环境"那一步会检查，安装 dsh 不会。
  空间不够时直接告诉你「需要约 X，当前只剩 Y」，而不是下载到一半失败。

### Upgrade notes

- ⚠️ **与安全有关的一条**：旧版本会把 API Key **加密存在实例目录里**。本版不再读它，
  所以启动时会**自动删除**这两个遗留文件（`credentials.env` / `credentials.enc`）。
  你的 Key 不会因此丢失 —— 现在生效的是 dsh 自己那份（在 dsh 界面里填。
  第一次进界面会有提示告诉你去哪填）。
- 如果你以前"点了启动但被弹窗挡住"：现在不会了。没配 Key 也能起，进去填就行。
- 实例数据（名称、配置、已装版本）**不会丢**，就地升级即可。
- ⚠️ **首次启动会比平时久一点**：运行环境里的脚本换了版本，App 会重新解压一遍脚本
  （只有几 MB，不影响 rootfs 主体）。

## 0.1.4-SNAPSHOT

> 本版**大量改动界面结构与实例管理方式**。

### Added

- **实例详情页**：点实例列表里的任意一项即可进入，页内三个标签 ——
  **运行**（状态、启动/停止、打开界面、体积、路径、运行时自检）、
  **日志**（**只看这个实例自己的输出**，从启动到停止）、**配置**（名称、模型、profile、端口、重装、删除）。
- **每个实例有自己的日志**：实例的输出不再和别的东西混在一起；同时仍保留一份**应用日志**
  （解压 / 安装 / 凭据 / 运行时这些启动器自己打的行），在 **设置 → 日志** 里看。
  两份日志各自落盘：应用日志 `logs/runtime.log`，实例日志 `logs/instance-<实例>.log`。
- **返回键现在成体系**：从任意子页面按返回会**逐层退回**（详情页 → 列表 → 首页），
  而不是一路把 App 退掉。左侧菜单的返回按钮走的是同一条链。

### Changed

- **主菜单从 5 项精简为 3 项**：**实例 / 版本 / 设置**。
  - 「下载」改名「**版本**」—— 这一页本来就是"有哪些版本可以装"，名字与内容对齐。
  - 「管理」去掉：它一直是个空占位页，职责已由实例详情（进程）与版本页（版本）承担。
  - 「日志」去掉：实例日志进了实例详情，应用日志进了设置页的子页。
- **设置页**现在是三个子页：**启动器设置 / 日志 / 关于**。
  同时删掉了设置里那三条「版本下载 / 实例管理 / 运行日志」的跳转行 —— 左侧菜单已经有它们了，
  同一件事给两个入口只会让人犹豫点哪个。
- 实例列表的左右留白从 12dp 改为 **10dp**，与侧边菜单、右侧面板对齐。

### Fixed

- **停止实例后 dsh 进程残留**：以前"停止"之后 rootfs 里的 dsh 进程可能还活着、继续占着端口，
  于是**下一次启动报 `EADDRINUSE`**（同一个实例第二次起不来）。本版从三个方向一起修：
  - 启动脚本把 dsh 进程的真实 pid 写出来，停止时**按 pid 精确终止**；
  - 停止信号换成 dsh 底座真正会响应的那个（以前发的信号它直接忽略，实际是靠强杀收尾，
    而强杀来不及清理子进程 —— 这才是残留的根因）；
  - 万一端口还是被占，**自动改用系统分配的端口**并写进日志，而不是丢一句"启动失败"。
- **"无法取得进程 pid"**：这条警告让"App 被杀之后仍在跑的实例"无法被识别和清理。
  根因是取值方式在 Android 上根本不成立（用了一个 Android 运行时不提供的方法）。
  现在补了一条从系统进程表读取的兜底路径。
- **首启准备页按返回会直接退出 App**：准备页是从启动画面直接进来的，任务栈里只有它自己，
  按返回等于把 App 关掉（用户以为崩了）。现在按返回是**回到桌面**，任务和正在跑的解压都留着，
  从最近任务点回来还能接着看。
- **从外壳进准备页再返回会叠出第二个主界面**：现在复用已有的主界面实例，不再新建。

### Upgrade notes

- **实例数据（名称、配置、已装版本）不会丢**，就地升级即可。
- 如果你曾经因为"停止后残留"而遇到过启动失败：**这一版修好了**，
  但建议升级后先重启一次手机（清掉之前残留的进程），再启动实例。

## 0.1.3-SNAPSHOT

> 本版**只更换运行时底座**（rootfs 瘦身），App 代码未改。

### Changed

- **APK 从 311 MiB 降到 153 MiB** —— 把 rootfs 里运行时用不到的部分剔掉了：
  - **GCC 开发环境**（`/usr/lib/gcc`、`/usr/include`、各 sanitizer 库、`lto-dump`）
  - `/usr/lib/python3.11`
  - perl 全家、`git-core`
  - man / doc / info 文档
  - 构建期缓存（`node-gyp` 头文件缓存、apt 索引与缓存）

  **保留**：`gcc`/`g++`/`make`/`pkg-config`/`python3`（各几 MB，作保险）、全部 `node_modules`
  与 Node 运行时、apt/dpkg/openssl/ssh、`en` + `zh` + `ja` + `ko` 等 locale。

  **依据**：dsh 的原生模块全部以 prebuild 形式分发（`node-pty` 自带 `linux-arm64` 二进制、
  koffi / sharp / node-addon 同理），运行时不需要编译器。

  实测数字：

| | 0.1.2 | 0.1.3 |
|---|---|---|
| `rootfs.tar.xz` | 314,360,800 B | **148,637,136 B**（−52.7%） |
| 解压后 | 1436 MB | **862 MB** |
| APK | 311 MiB | **153 MiB** |
| 首次解压所需空闲空间 | ≥2 GB | **≥1.5 GB** |

### Upgrade notes

- 底座换了版本串，App 会**自动重新解压** rootfs（旧的会被替换）。
- 请预留 **≥1.5 GB** 空闲空间。
