# 版本说明（面向用户）

> 本文件是**公开发布**的版本说明 —— 每个版本一段，写清"这一版对你有什么变化"。
> GitHub Release 的正文就取自这里。
>
> 最新版本在最上面。格式参照 [Keep a Changelog](https://keepachangelog.com/)。
>
> **版本号只有一个真源**：仓库根 `gradle.properties` 的 `dshVersion`。
> 本文件里最新的那个版本号必须与它一致。
>
> ⚠️ **历史段落的已知失真**：早期版本（fix1 ~ fix7）的"升级须知"里写的"首次启动会重新解压
> 脚本（几 MB）"，体积实测只有 **约 34 KB**（`scripts` 子目录合计 34 013 B），且对**已装过**
> 的用户并不会自动发生（fix10 起才在启动时真正比对脚本版本）。这些段保留原文作为历史记录，
> **以最新一段为准**；不要再据此估算升级耗时。

## 0.1.6-SNAPSHOT（fix22，当前验证包）

> **0.1.6 的第二十二轮**——两件事：**别再问你刚回答过的问题**，以及**给外部浏览器补上前端静态
> 资源的缓存头**；另附对"每次打开到底要下多少"的重新测量与更正。

### 修复（复制链接后不再重问门禁）

- **复制成功后不再把同一个框摆回来**：此前点「复制链接」、链接进了剪贴板，两秒后界面又弹出
  「仍要继续 / 复制链接 / 用外部浏览器打开」——问的是你刚做过的选择。现在复制**成功**后停在一块
  「链接已复制。到浏览器里粘贴打开即可；想在应用内打开时点「重试」。」面板上，带重试 / 日志 /
  停止 / 关闭四个出口；从浏览器切回 App 也不会再被问一次。
- **没复制成功、或取消了确认框时行为不变**：仍回到门禁框让你重新决定；只有"链接确实进了剪贴板"
  这一种情况才走新路径。
- **没解决的两点先说清楚**：退出再进界面仍会提示一次（标记只活在当前页面里，没有持久化——存下来
  会让这台设备永远不再提示 WebView 过旧，而那是你知道"内嵌界面会崩"的唯一机会）；开着确认框时
  若恰好发生一次状态回放（比如按 Home 再回来），门禁框仍会被重摆一次。

### 修复（外部浏览器：给前端静态资源补缓存头）

- **`/assets` 下的文件现在带 `cache-control: public, max-age=31536000, immutable`**。dsh 自己的
  前端服务只写 `content-type`、不发任何缓存头，所以外部浏览器每次打开都要把前端文件重下一遍。
  启动器挂了一个约 130 行的小插件（`launcher-assets`）只补这一句头；文件名里本来就有内容哈希，
  `immutable` 是安全的。实测 gzip 仍生效（77 KB 的 CSS 压到 19 KB），`../` 与 `%2e%2e` 都 404；
  插件万一加载失败只打一行 warning，界面退化为原来无缓存的样子，不会因此起不来。
- **dsh 开发用的热更新轮询从每 0.5 秒拉长到每 5 秒**（proot 里每次 stat 都要过一次 ptrace）。
  这只省持续底噪 CPU，不改变打开速度。那个插件（`client-hmr`）没有整个关掉——它是"装完插件、
  页面不刷新就出现"的唯一通路，关掉后插件页仍会显示「已生效」，你会看到"装好了、显示已生效、
  页面上却没有"；静默半失效比明说「请重启」更糟。

### 更正（每次打开到底要下多少）

- **首屏真实下载量约 5 MB**。此前只量了 dsh 前端的 `dist`，漏掉了**58 个客户端插件包**——它们
  不是按需加载，首屏就以 `modulepreload` 整批注入（未压缩 9.27 MB，gzip 后 **4.42 MB**）。
  加上 dist 与字体，首屏是 ~5 MB 量级。以下数字是逐文件量出来的，不是估的。
- **这 5 MB 里只有一部分是每次都要重下的**：插件包走 `/plugins`，带 `immutable` 缓存（那 4.42 MB
  只在第一次、或 combo 的 `rev` 变了之后下载）；`dist` 那约 2 MB 原本每次导航都重下，**这一版的
  `/assets` 缓存插件已经修掉**。⇒ 首次打开约 5 MB，之后基本不用再重下。

### 升级须知

- **直接覆盖安装**（fix21 → fix22 无需卸载）。
- **脚本已更新（11 → 12）**：升级后**首次启动会走一次准备页**重新解压脚本（秒级，不动 rootfs 与
  实例数据），之后不再重复。带 `--patch` 启动若在就绪前退出，脚本会自动去掉 `--patch` 重试一次
  ——优化项永远不该成为"起不来"的原因。
- 质量基线：单测 **513/513**、脚本自检 **28/28**；本轮新增的测试专门盯"调用点真的接上了"，
  并做了 5 次变异验证（把实现改回旧行为，测试必须变红）。

## 0.1.6-SNAPSHOT（fix21，历史验证包）

> **0.1.6 的第二十一轮**——**先更正上一版说错的三件事**，再给"空目录"这个踩了三次的坑加上自动
> 告警，并补一条不依赖列表加载的自救路。

### 更正（上一版说错的）

- **「前端包不压缩」是错的**：dsh 的前端包**是** gzip 压缩的（压缩级别 1，超过 1 KB 才压）。
  此前把未压缩体积当成了实际传输量。
- **「WebView 114 解释了界面慢」是错的**：你是在**外部浏览器**里操作，那个客户端根本不用系统的
  WebView。这条只解释"App 内嵌界面在旧机型上可能崩"，与"外部浏览器慢"无关——两件事写混了。
- **「1.35 MB 每次重传」是未压缩体积**："每次刷新要重新下发一遍"这个结论仍然成立（前端资源确实
  没有缓存头），但那个数字不是实际传输量；真实量级见上一段（fix22）的重新测量。

### 修复（空目录现在会自己说出来）

- **启动时检查生效的「启动目录」里有没有子目录**，没有就在日志里写一行 `WARN home-has-no-subdir`。
  这个坑连续踩了三次（`/root` 空 → `workspace` 空 → 自定义目录不存在），每次症状都一样：对话框
  打开是空框、**没有任何报错**。以后把日志发过来，能直接看出是不是这个原因。
- **多一条自救路**：列表一直出不来时，对话框**路径行右边有一个铅笔图标**，点它可以**手打路径**
  ——照抄设置页「启动目录」里显示的路径即可，这条路不依赖列表加载。
- **设置页「启动目录」的说明补全**：改完**重启后生效**；只有 `workspace` 是对的，`node_modules`
  和 `home` 都不要选（`home` 里放着你的 API Key）。
- **「打开」按钮的行为写清楚了**：**没点任何目录直接按「打开」，选中的是当前那一层目录本身**
  （会建出一个名字像 `inst-1792…` 的工作区）。要选 `workspace`，**先点它，再按「打开」**。

### 两种症状其实是两种病

- **空框、没有转圈** = 列表成功返回但条目是 0，即"启动目录是空的"，本次已修；**右下角「加载中…」**
  = 请求发出去了但超过 0.3 秒没回来，是另一条路径，与"目录是不是空的"无关。之后若仍看到
  「加载中…」，请用铅笔图标手打路径绕过，并把日志发出来（看有没有 `home-has-no-subdir` 即可区分）。

### 升级须知

- **直接覆盖安装**（fix20 → fix21 无需卸载）。
- 脚本未改（标记仍是 11），升级后启动**不会**重解压。

## 0.1.6-SNAPSHOT（fix20，历史验证包）

> **0.1.6 的第二十轮**——第三轮锐评的结果。**最要紧的一条：不要把实例的 home 目录选成工作区。**

- 「选择工作区目录」的列表里会看到 `home` 和 `workspace` 两项。**`workspace` 才是该选的**

  `home` 选成工作区，agent 就能读到你的 API Key。设置项的说明里也加了这句提醒。

- **设置项说明补了两件事**：①改「启动目录」**重启后生效**（之前没说，你会以为立刻变了）；
  ②上面那条 API Key 的提醒。

  里会明确写"刚建了一个空的启动目录，如果这是拼写错误请回去改"。

- **「加载中…」可能永远不消失**：dsh 的前端**没有请求超时**（全文只有 3 个 `setTimeout`，没有一个
  是请求上限），请求卡住时那个提示会一直挂着。这同样是上游行为。

## 0.1.6-SNAPSHOT（fix16，历史验证包）

> **0.1.6 的第十六轮**——让**外部浏览器**能长期正常使用 dsh：新增「在浏览器中打开」，
> 并让每个实例的端口稳定下来。

### 为什么外部浏览器又慢、又选不了目录

- 两件事同一个根源：**外部浏览器里的登录凭据总是失效**。dsh 每次启动都会生成**新的访问 token**，
  你上次复制的链接过一会儿就作废；登录 cookie 的名字里还编着「主机:端口」，端口一变 cookie 就
  直接失效。而 App 内的 WebView 一直很快，因为它自己保存着一份**有效期 30 天的 cookie**。
- 凭据一失效，页面本身还能打开（HTML/CSS/JS 是公开的），但**所有动态数据都拿不到**——表现就是
  "能打开但慢得要命"，以及"点选择工作区目录一直在转/空着"。

### 修复

- **新增「在浏览器中打开」**（实例详情 → 运行环境段），与「复制访问链接」并列但用途不同：
  **复制**给你一条地址，但**只在当下几分钟内有效**（token 会换新）；**打开**是**当场**把当前真实
  地址交给浏览器，零过期风险。拿不到凭据时这一行会灰掉，不摆一个点了必然失败的按钮。

## 0.1.6-SNAPSHOT（fix11，历史验证包）

> **0.1.6 的第十一轮修复包**——这一轮修的是**"点了停止却停不掉、进程变成孤儿"**这一类问题。
> 触发场景：dsh 启动时在某些机型上会被系统安全机制拦下，App 会自动换个方式重试一次；但那个重试
> **从来没真正发生过**，界面空转三分钟后报"启动超时"，而后台可能还留着一个杀不掉的 proot 进程
> （占内存、占端口，点停止也没反应）。**装 `…-fix11-arm64.apk`**（关于页应显示 `0.1.6-SNAPSHOT-fix11`）。

### 修复（启动重试与停止可靠性）

- **启动失败后的自动重试现在真的会执行了**：原来"检查是否已经在运行"只看状态不看进程是否真的活着，
  于是重试被误判成"已经在跑，复用现有进程"而直接跳过——新进程根本没启动，界面却一直等。
  现在会同时核对「状态属于这个实例」「状态是启动中/运行中」「**进程确实还活着且是本实例的**」三件事。
- **停止超时的等待时长修正**：原来等 8 秒就判定超时，但真正停一个实例最坏要约 12 秒
  （先请求优雅退出、再逐级升级信号、最后校验），于是"刚停就又点启动"这个常见操作永远走超时分支。
  改为 13 秒。
- **停止失败不再丢失线索**：原来停止一开始就把进程句柄清掉，一旦终止失败就再也找不到它了。
  现在只有确认终止成功才清；失败时句柄和 pid 文件都保留，下次还能重试。
- **进程身份校验**：系统会把已退出进程的 pid 复用给别的进程。现在判断"是不是我那个进程"时会核对
  命令行里是否含本实例标识，避免把别人的进程当成自己的而复用。
- **认领不再覆盖失败态**：App 重启后"接管还活着的实例"时，原判据会把"上次启动失败"的实例也当成
  "没有实例在跑"而接管，覆盖掉失败原因。现在只在真正空闲时才接管。

### 变化（用户可见）

- **"正在停止"现在看得见了**：实例卡片和详情页在停止过程中会显示「正在停止…」并置灰不可点。
  原来显示的是一个可点的「停止」，点下去毫无反应，看起来像卡死。
- 其余界面行为不变。

### 升级须知

- **直接覆盖安装**（fix10 → fix11 无需卸载）。
- 脚本未改（标记仍是 10），**升级后启动不会重解压**。

### 修复（`authentication required` 依旧存在 —— 根因已找到）

- **根因**：这个 401 页面只会来自**外部浏览器**，而且只在一种场景出现 —— **App 被系统杀掉后
  重进**（此时 dsh 进程还活着，App 会"认领"它并直接显示运行中）。认领时 App 手里没有任何
  访问凭证（凭证只在那次启动时出现过一次，且日志里已脱敏），于是**"用外部浏览器打开"发给
  浏览器的地址里没有凭证，浏览器首次访问必然 401**。
  - **修复**：App 现在把带凭证的地址**安全地持久化**在实例的私有目录里（随进程生灭，停止即
    清除），认领时读回 —— 修复后，"杀 App 重进 → 打开界面 → 用外部浏览器打开"这条路径
    会像正常启动一样直接进入 dsh，不再看到 401 英文页。
  - **旧安装兼容**：升级上来的第一次认领若读不到持久化凭证（旧文件没有这个字段），会在日志里
    明确记一行，此时外跳可能仍 401（回退行为与 fix3 相同）——**正常启动一次实例后即恢复**。
- **顺带修复一个 fix3 引入的回归**：fix3 新增的"端口兜底"在三行启动输出之间有一个毫秒级的
  窗口，可能把地址短暂降级成无凭证版本（外部极难撞上，本次一并消除）。

### 修复（"进入时有时不弹版本低提示"）

- **机制**：这是"提示过一次就不再提示"的设计（防止反复打扰）+ 页面保活共同造成的 ——
  你在对话框里选过"仍要继续"后，之后**所有加载**（含实例重启后的自动重载）都不再弹框。
  若你选的"继续"实际落在崩坏的页面上（WebView 过旧的设备会发生），就只剩白屏且不知原因。
- **修复（两层）**：
  - **检测到页面因 WebView 过旧而崩坏时，会再弹一次提示**，这次带上**升级方法**的说明
    （去哪里更新 WebView）和一个"用外部浏览器打开"的出口；
  - **版本门槛从 116 上调到 119**：实测 dsh 新版前端需要 119，116~118 的设备此前会被
    放行但必崩 —— 现在会正确提示"过旧"。
- **提醒**：WebView 过旧（如 114）的设备，**首选把「Android System WebView」（部分设备为
  Chrome）更新到最新版**；不升级的话应用内界面仍会崩坏（这是 dsh 前端的要求，启动器无法绕过）。

### 修复（其它小项）

- **"停止后 proot 仍存活"的误报**：停止后的清理窗口从 1 秒延长为两段（1+4 秒）——
  node 进程树较大时收尾本来就可能超过 1 秒，旧实现会把正常收尾误记为异常。

### 升级须知

- 从 fix3 或更早版本**直接覆盖安装**即可，实例数据、配置**不受影响**。
- 本轮**建议重点回归**：
  ①启动实例 → 杀 App（划掉后台）→ 重进 → 打开界面（该显示运行中）→ 选"用外部浏览器"
  （该正常进入 dsh，不再 401）；

## 0.1.6-SNAPSHOT

> **这是给真机首验的包（对照基准）**。当前验证包是 **fix2**——不要装本包，除非做对照测试。
> 本版只做一件事：**让 App 在真机上第一次真正跑通**
> —— 装上 → 装 dsh → 启动 → 在界面里对话 → 停止 → **再次启动不再报端口被占**。
> 界面结构、按钮位置与 0.1.5 完全一样；改的全是"让第一步能走通"的底层问题。

### 修复

- **「停止」以后 dsh 其实没停干净 → 下次启动报端口被占（`EADDRINUSE`）**。
  上一版让你"能起来一次"，但停不彻底。根因是**停止信号发给了错误的进程**：真正在跑的
  dsh 是 Linux 子进程，而旧代码把信号发给了外层的"翻译器"，那个进程**故意忽略**了它。
  现在改成用**该翻译器唯一会响应**的信号，让它带走整棵子进程树。
- **取消安装 / 安装超时后，后台的下载进程杀不掉**（同一个根因，安装路径也一并修了）。
- **「停止」后马上「启动」有时新旧两个进程会抢同一个端口**。现在启动前会**等上一个真正退干净**再起。
- **手动设的端口会被自动换掉后永久覆盖**。现在只有你没固定端口时才自动分配。
- **少数日志会丢**：日志刷新正好和写入撞上时，那几行可能既不显示也不落盘。已修。

### 变更

- **首次运行环境的解压期间会保持 CPU 唤醒**：解压要几分钟，以前手机灭屏可能把它掐断/挂起，
  现在解压期间不让系统睡着，解压一结束立即放开（不影响平时耗电）。
- **磁盘空间要求算准了**：旧版按"瘦身前"的旧数字算，会把本来够用的手机误判成"空间不足"。
  现在按实际大小：首次安装约需 **1.4GB** 空闲，升级约 **862MB**。
- **安装自检、DNS 就绪判断、脚本交互**三处脚本层面的小问题修掉（自检更少误报、安装更少卡住）。

### 升级须知

- 这版**专为验证端到端流程**，装上后请用应用内「设置 → 运行时自检」
  把「装 → 启 → 对话 → 停 → 再启」走一遍。任何一步失败，请把日志（应用内日志页 /
  `logs/runtime.log`）原样记下来反馈。
- 实例数据、配置**不受影响**，就地升级即可。

## 0.1.5-SNAPSHOT

### 新增

- **任务区现在会说"结果"**：以前只显示"正在进行"，取消或失败之后那一行**瞬间消失**，
  用户看不到发生了什么。现在完成 / 失败 / 已取消都会留在列表里（保留最近 20 条），
  失败会带上原因；取消与停止也换成了两张不同的图标（原来长得一样）。
- **首次进界面时会提示去哪填 API Key** —— 只提示一次，之后不再打扰。

### 变更

- **API Key 完全由 dsh 自己管**：启动器不再保存、不再注入、也不再在启动前检查。
  - 表现上的变化：**没配 Key 也能启动**（以前会弹一个"尚未配置 API Key"的框挡住），
    起不来的是对话而不是整个实例。填 Key 的位置在 **dsh 界面里 → 设置 → 模型**。
  - **为什么必须这么改**：dsh 把"从启动环境继承来的 Key"视为最高优先级且**只读**，
    一旦启动器注进去，你在 dsh 的模型页里改 Key 会**直接被拒绝**（报错），
    等于在 App 里无论如何都改不掉。所以这不是取舍，是必须去掉。
- **实例详情里的"模型"设置行去掉了**：查证后确认那一项**从来没生效过** ——
  它对应的是一个并不被 dsh 读取的环境变量（同名常量在 dsh 里是另一个东西）。
  模型请到 **dsh 界面 → 设置 → 模型** 里选。
- **界面皮肤按 FCL 原版逐个对齐**（这一项看起来琐碎，但"塑料感"基本都来自它）：
  - **实例卡片在暗色下不再发白**（`auto_tint` 挂在错误的控件类上，一直静默失效）；
  - **图标不再全是默认黑色**（着色只对背景生效，以前挂在 `src` 上等于没上色）；
  - **切换亮暗主题后，已显示的行不再停在旧配色上**；
  - 日志页不再用自创的深色终端配色，改用与主题配套的一套，亮暗各一份；
  - 一票尺寸/留白/层级的对齐：页面左右留白、右面板内边距与标题字号、设置行的点击反馈、
    开关行高、组标题弱化、版本行的安装按钮改图标、任务区与其它列表统一。

### 修复

- **取消安装后"安装中"再也不消失**（要重启 App 才恢复）：取消时没有发出"结束"信号，
  界面永远等不到。现在取消有明确终态，且不会再闪一下"安装失败"。
- **"停止"可能停掉另一个实例**：任务行的停止动作没校验归属，从渲染到点击之间状态一变就停错。
- **运行时准备失败几乎看不到原因**（只在极短的竞态窗口里闪一帧）—— 现在会留在任务区。
- **安装失败记录无限增长**（内存缓慢泄漏）—— 失败后也做一次清理，原因不会丢。
- **安装失败时会告诉你真正的原因了**：以前不管什么原因，界面上只有一句
  「安装失败（详见日志）」。原因是**认不出新版本 npm 的报错格式**
  （npm 10 把错误行前缀从 `npm ERR!` 改成了 `npm error`），于是一条错误都没被收集到。

- **"三个点"紧贴着"启动/重试"按钮、容易误触**：把它的可点区域从 20dp 撑到 40dp

## 0.1.4-SNAPSHOT

> 本版**大量改动界面结构与实例管理方式**。装之前请先看「升级须知」。

### 新增

- **实例详情页**：点实例列表里的任意一项即可进入，页内三个标签 ——
  **运行**（状态、启动/停止、打开界面、体积、路径、运行时自检）、

- **每个实例有自己的日志**：实例的输出不再和别的东西混在一起；同时仍保留一份**应用日志**
  （解压 / 安装 / 凭据 / 运行时这些启动器自己打的行），在 **设置 → 日志** 里看。
  两份日志各自落盘：应用日志 `logs/runtime.log`，实例日志 `logs/instance-<实例>.log`。
- **返回键现在成体系**：从任意子页面按返回会**逐层退回**（详情页 → 列表 → 首页），
  而不是一路把 App 退掉。左侧菜单的返回按钮走的是同一条链。

### 变更

- **主菜单从 5 项精简为 3 项**：**实例 / 版本 / 设置**。
  - 「下载」改名「**版本**」—— 这一页本来就是"有哪些版本可以装"，名字与内容对齐。
  - 「管理」去掉：它一直是个空占位页，职责已由实例详情（进程）与版本页（版本）承担。
  - 「日志」去掉：实例日志进了实例详情，应用日志进了设置页的子页。
- **设置页**现在是三个子页：**启动器设置 / 日志 / 关于**。
  同时删掉了设置里那三条「版本下载 / 实例管理 / 运行日志」的跳转行 —— 左侧菜单已经有它们了，
  同一件事给两个入口只会让人犹豫点哪个。
- 实例列表的左右留白从 12dp 改为 **10dp**，与侧边菜单、右侧面板对齐。

### 修复

- **停止实例后 dsh 进程残留**：以前"停止"之后 rootfs 里的 dsh 进程可能还活着、继续占着端口，
  于是**下一次启动报 `EADDRINUSE`**（同一个实例第二次起不来）。本版从三个方向一起修：
  - 启动脚本把 dsh 进程的真实 pid 写出来，停止时**按 pid 精确终止**；
  - 停止信号换成 dsh 底座真正会响应的那个（以前发的信号它直接忽略，实际是靠强杀收尾，
    而强杀来不及清理子进程 —— 这才是残留的根因）；
  - 万一端口还是被占，**自动改用系统分配的端口**并写进日志，而不是丢一句"启动失败"。
- **"无法取得进程 pid"**：这条警告让"App 被杀之后仍在跑的实例"无法被识别和清理。
  根因是取值方式在 Android 上根本不成立（用了一个 Android 运行时不提供的方法）。
  现在补了一条从系统进程表读取的兜底路径。
- **首启准备页按返回会直接退出 App**：准备页是从启动画面直接进来的，任务栈里只有它自己，
  按返回等于把 App 关掉（用户以为崩了）。现在按返回是**回到桌面**，任务和正在跑的解压都留着，
  从最近任务点回来还能接着看。
- **从外壳进准备页再返回会叠出第二个主界面**：现在复用已有的主界面实例，不再新建。

### 升级须知

- **实例数据（名称、配置、已装版本）不会丢**，就地升级即可。
- 如果你曾经因为"停止后残留"而遇到过启动失败：**这一版修好了**，
  但建议升级后先重启一次手机（清掉之前残留的进程），再启动实例。
