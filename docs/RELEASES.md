## 0.1.6-SNAPSHOT（fix6，当前验证包 —— ⚠️ 首次换身份：新 App，旧包可并存）

> **0.1.6 的第六轮修复包**——本轮的重点：**五路独立审查后的 18 项修复**（任务区文案、配置页
> 重装确认与删除反馈、启动链保活、删除实例时取消安装、日志清理等）、以及**提前切换出货身份**：
> 正式包名（去掉 `.debug` 后缀）+ **全新签名密钥**（不再用公开的调试密钥）。
> **装 `…-fix6-arm64.apk`**（关于页/系统应用信息应显示 `0.1.6-SNAPSHOT-fix6`）。

### ⚠️ 升级须知（本轮特殊！先读这条）

- **fix6 是一个"全新 App"**：此前所有版本（含 fix5）的包名都带 `.debug` 后缀
  （`com.dsh.fcl.androidlauncher.debug`），fix6 起改为正式包名
  （`com.dsh.fcl.androidlauncher`）。系统把它们视为**两个不同的应用**——
  - **不用卸载旧版也能直接安装 fix6**（两者可以并存，不会冲突）；
  - 但**旧 App 里的数据不会带过来**：实例列表、已解压的运行环境、dsh 里的 API Key
    都需要在 fix6 里**重新准备一次**（重新解压约几分钟 + 在 dsh 界面重填 Key）。
- **想保留旧版观察对比**：不卸载即可（旧包名照常运行）；**想回收空间**（一个实例动辄
  几百 MB + 运行环境约 1.5 GB）：确认 fix6 稳定后用系统设置卸载旧的那个 `.debug` 版即可。
- **为什么必须换**：旧包用的是与上游 FCL 项目公开的调试密钥（任何人都能签同名"更新"
  顶替），且旧包是 debuggable 的。fix6 起两件事一起修：新私钥只有作者持有 + 出货包不再
  debuggable。包名与签名一起换，是"旧身份的账一次性勾销、新身份从此干净"。
- **此后所有版本都能正常覆盖升级**（fix6 → fix7 → …），不会再要求任何卸载或重装。

### 修复（五路审查的结论，本机+真机验证中）

- **配置页「重新安装」现在有确认框，且会先停掉正在跑的实例再重装**（此前一键点下去直接开装，
  可能与运行中的 dsh 抢写文件，也不问你一声）。
- **配置页「删除」现在有明确反馈**：点了删除会提示"正在删除…"，删除不干净（有文件残留）
  也会告诉你，不再"页面一消失不知道成功没有"。
- **任务区的阶段文字不再露英文**：中文界面下「启动中/停止中/删除中」此前显示的是
  Starting/Stopping/Deleting，现在跟着语言走。
- **启动过程中切走页面，实例也能"完整地"起来**：以前在启动等待中切到别的页，可能出现
  "实例在后台跑，但通知栏没有它、也不自动进界面"；现在不会了（前台服务与提醒不再依赖当前页面）。
- **删除一个正在安装的实例，会先取消安装并等它收尾**（此前可能与正在写入的安装过程抢文件，
  甚至在特殊情况下让已删除的实例"复活"）。
- **修改名称/端口时，若实例正在运行，会提示"重启后生效"**；端口输错会重新打开输入框
  （预填你刚才输的内容），不用从头再敲。
- **清理了含明文访问凭证的启动日志**：现在自动轮转（只保留最近几份 + 超过 7 天自动清），
  不再无限堆积。
- **若干文案修正**：路径复制提示改为"已复制"；版本页失败提示不再夹带英文技术术语；
  关于页打不开链接时会提示并自动复制链接；安装一次只提示一次（不再 Toast + 弹窗重复）。
- **设置页「运行环境自检」连点不再叠出多个对话框**（改为"正在自检…"提示）。

### 已知边界（承接 fix5）

- 401（`authentication required`）的修复与验证方法同 fix5（先清浏览器 cookie 再测）。
- WebView < 119 的设备仍会提示，建议升级系统 WebView 或走外部浏览器。

### 升级须知（常规）

- 本轮建议回归：①配置页重装（应有确认框、运行中会先停）；②删除实例（有"正在删除"提示）；
  ③中文界面任务区文案；④启动中切页再回来（实例应正常带通知运行）；⑤改端口提示重启生效。

## 0.1.6-SNAPSHOT（fix5，历史验证包）

> **0.1.6 的第五轮修复包**——本轮的重点是：**把 401 修复真正做到全覆盖**（上一轮的修复有两个
> 真实缺口，见下）、**修复"版本显示"与"日志界面遮挡"两个体验问题**、以及**把发布渠道补齐**
> （fix3/fix4 已补发到 Release 页；本包 fix5 先本机验证、通过后再发布）。
> **装 `…-fix5-arm64.apk`**（关于页/系统应用信息应显示 `0.1.6-SNAPSHOT-fix5`）。

### 修复（`authentication required` —— 把上一轮的两个缺口堵上）

- **上一轮（fix4）修复了两个缺口**（本轮已根治）：
  - **缺口一**：如果你手机上运行中的 dsh 是**旧版本包启动的**（升级 App 不打断已运行的 dsh——
    这是设计内的正常状态），旧的进程记录文件里没有我们需要的"访问凭证"，升级后第一次"认领"
    这台还在跑的 dsh 时拿不到凭证 → 外跳浏览器仍会 401，**且一直持续到你手动停止/重启实例为止**。
  - **缺口二**：dsh 启动后的头一两秒内（凭证还没打出来）App 被杀，重启认领时同样拿不到凭证。
- **本轮修复（探活式恢复）**：App 现在从**三个来源**恢复访问凭证（进程记录 → 专用凭证文件 →
  dsh 启动日志），并把恢复出的每个候选**实际打到运行中的 dsh 上验证**（有效凭证 → 服务端
  回"重定向/通过"，失效 → "拒绝"，两者可精确区分）。只要 dsh 还活着，就能恢复出**当前有效**
  的凭证——**所有代次的旧包（含 fix2/fix3 时代启动的进程）都被覆盖**。
- 该功能在 **fix2/fix3/fix4 上都不存在**（这是本轮新写的）；如果你之前"装的是 fix4 却仍 401"，
  与本条吻合。

### 修复（体验两则）

- **弹出"WebView 过旧"提示时，现在会自动退出日志界面**：此前对话框压在日志层上，两个界面
  互相遮挡；现在弹框前先收起日志层，让你直接面对提示与选择。
- **日志第一行新增版本横幅**：每次 App 启动，日志开头会写一行 `[app] launcher=0.1.6-SNAPSHOT-fix5
  (code=111)`——以后贴日志排障时，第一行就能看出装的是哪个包。

### 发布说明（重要）

- **fix3/fix4 已补发到 Release 页**（2026-10-17；此前只在本机、从未上传——请不要再从旧渠道
  取包，一律以 [Releases 页](https://github.com/sqkl520/dsh-fcl-android-launcher/releases) 为准）。
- **fix5（本包）暂未上传**，先在本机验证；验证通过后再发布。无论从哪取包，请到**关于页核对
  版本号后缀**（本包应为 `-fix5`）确认装对。
- **验证 401 修复前，请先在系统浏览器里清一次该站点的缓存/cookie**（浏览器里 127.0.0.1
  的历史记录）——如果浏览器此前从未成功进入过 dsh，清理无副作用；若曾成功过，清理是为了
  确实测到"首访"路径。

### 升级须知

- 从任何旧版本**直接覆盖安装**即可，实例数据、配置**不受影响**。
- 本轮**建议重点回归**：
  ①**主链**：升级后**不要手动停止实例**，直接杀 App 重进（实例显示"运行中"=已认领）→
  打开界面 → 选"用外部浏览器打开" → 浏览器**应直接进入 dsh**（先清浏览器 cookie 再测）；
  ②装好后第一时间去**关于页核对版本号 = `0.1.6-SNAPSHOT-fix5`**（这是本轮修复是否真装上的判据）；
  ③开着日志时触发"WebView 过旧"提示 → 日志层应先收起再弹框；
  ④日志第一行应出现 `[app] launcher=…` 横幅；
  ⑤正常启动/停止/对话一条龙无回归。

## 0.1.6-SNAPSHOT（fix4，历史验证包）

> **0.1.6 的第四轮修复包**——本轮专门解决你反馈的「**`dsh web authentication required` 提示依旧存在**」
> 与「**进入时有时不弹版本低提示**」两个问题，另外**版本显示现在会带上 fix 轮次**
> （关于页/系统应用信息里显示 `0.1.6-SNAPSHOT-fix4`，一眼看出装的是第几轮修复）。
> 前者的根因已经通过本地实验精确定位并修复；后者是"提示策略"的缺口，也一并补上。
> **装 `…-fix4-arm64.apk`**（fix3/fix2/base 保留作对照基准）。

### 修复（版本显示不准确）

- **版本号现在包含修复轮次**：关于页与系统「应用信息」里此前只显示 `0.1.6-SNAPSHOT`
  （看不出是第几轮修复包），现在显示 `0.1.6-SNAPSHOT-fix4`。安装包文件名同上。

### 修复（`authentication required` 依旧存在 —— 根因已找到）

- **根因**：这个 401 页面只会来自**外部浏览器**，而且只在一种场景出现 —— **App 被系统杀掉后
  重进**（此时 dsh 进程还活着，App 会"认领"它并直接显示运行中）。认领时 App 手里没有任何
  访问凭证（凭证只在那次启动时出现过一次，且日志里已脱敏），于是**"用外部浏览器打开"发给
  浏览器的地址里没有凭证，浏览器首次访问必然 401**。
  - **修复**：App 现在把带凭证的地址**安全地持久化**在实例的私有目录里（随进程生灭，停止即
    清除），认领时读回 —— 修复后，"杀 App 重进 → 打开界面 → 用外部浏览器打开"这条路径
    会像正常启动一样直接进入 dsh，不再看到 401 英文页。
  - **旧安装兼容**：升级上来的第一次认领若读不到持久化凭证（旧文件没有这个字段），会在日志里
    明确记一行，此时外跳可能仍 401（回退行为与 fix3 相同）——**正常启动一次实例后即恢复**。
- **顺带修复一个 fix3 引入的回归**：fix3 新增的"端口兜底"在三行启动输出之间有一个毫秒级的
  窗口，可能把地址短暂降级成无凭证版本（外部极难撞上，本次一并消除）。

### 修复（"进入时有时不弹版本低提示"）

- **机制**：这是"提示过一次就不再提示"的设计（防止反复打扰）+ 页面保活共同造成的 ——
  你在对话框里选过"仍要继续"后，之后**所有加载**（含实例重启后的自动重载）都不再弹框。
  若你选的"继续"实际落在崩坏的页面上（WebView 过旧的设备会发生），就只剩白屏且不知原因。
- **修复（两层）**：
  - **检测到页面因 WebView 过旧而崩坏时，会再弹一次提示**，这次带上**升级方法**的说明
    （去哪里更新 WebView）和一个"用外部浏览器打开"的出口；
  - **版本门槛从 116 上调到 119**：实测 dsh 新版前端需要 119，116~118 的设备此前会被
    放行但必崩 —— 现在会正确提示"过旧"。
- **提醒**：WebView 过旧（如 114）的设备，**首选把「Android System WebView」（部分设备为
  Chrome）更新到最新版**；不升级的话应用内界面仍会崩坏（这是 dsh 前端的要求，启动器无法绕过）。

### 修复（其它小项）

- **"停止后 proot 仍存活"的误报**：停止后的清理窗口从 1 秒延长为两段（1+4 秒）——
  node 进程树较大时收尾本来就可能超过 1 秒，旧实现会把正常收尾误记为异常。

### 升级须知

- 从 fix3 或更早版本**直接覆盖安装**即可，实例数据、配置**不受影响**。
- 本轮**建议重点回归**：
  ①启动实例 → 杀 App（划掉后台）→ 重进 → 打开界面（该显示运行中）→ 选"用外部浏览器"
  （该正常进入 dsh，不再 401）；
  ②WebView 过旧的设备：对话框选"继续"后页面崩坏时，该**再弹一次带升级说明的提示**；
  ③正常启动/停止/对话一条龙无回归。

## 0.1.6-SNAPSHOT（fix3，历史验证包）

> **0.1.6 的第三轮修复包**——本轮做的是「**日志体验完全体 + 收尾硬化**」：把你反馈里
> **最顽固的日志滚动问题**根治（上滑不再被拽回），日志页性能与观感补齐（还能给新出现的行
> 一个淡入动画），另修了一批"不炸但在角落里硌人"的问题（首次进日志的跟随、菜单点击动画、
> 重复弹窗、切语言被弹回首页等）。**装 `…-fix3-arm64.apk`**（fix2/base 保留作对照基准）。

### 修复（你反馈过、这轮才根治的）

- **上滑读历史时，日志自己往上跑/被拽回底部（你说的"回不到历史"）**：这是两层机制的叠加，
  fix2 只修掉了其中一层。这轮把剩下的那层也治了——**现在你手指一上滑，日志就自动停下跟随**，
  不用再去关「自动滚动」开关；滚回底部（或点「回到底部」）才恢复跟随。这是成熟日志查看器的
  标准行为，也是你反馈里"回到底部/回不到历史"的根本解。
- **日志页偶尔卡顿**：把"判断每一行是什么级别"的重活从**每次刷屏时**挪到了**写入日志时**
  （一次算好、渲染直接读），日志页的滚动顺滑度应有可感提升。
- **日志新行**（你之前提的「希望日志出现时有动画」）：新出现的行现在会**淡入**（颜色从底板
  渐显到正文色），一次刷一批一起显，不晃眼。

### 修复（其它收尾）

- **点左侧菜单没有反应了**（重要回归，本轮引入本轮修掉）：菜单点击动画接线的同时误伤了菜单
  的选中逻辑，导致点击菜单不再切页。**已修**——点击菜单既播放动画、也正常切页。
- **菜单点击现在有动画**：点左侧菜单会有"旋转+回弹"的动效（对齐 FCL 原版手感）。
- **同一个启动失败会弹两次框**：现在只弹一次。
- **在设置里切语言后被弹回首页**：现在会留在你原来所在的页面（设置页）。
- **退出日志页后再进、或切回语言页时，已关闭的详情页会自己重新弹出来**：已修。
- 首次进入日志页的**跟随行为**、日志空态、若干提示文案的一致性收尾。

### 升级须知

- 从 fix2 或更早版本**直接覆盖安装**即可，实例数据、配置**不受影响**。
- 本轮改动集中在**日志页、外壳菜单、导航**三处，**建议重点回归**：
  ①进日志页→上滑读历史（不该被拽回）；②点左侧菜单（该切页且有动画）；
  ③在设置里切语言（不该被弹回首页）；④日志页滚动是否比 fix2 顺滑。

## 0.1.6-SNAPSHOT（fix2，历史验证包）

> **0.1.6 的第二轮修复包**（修完真机反馈第四轮 11 条 + 两轮全量审计的存量缺陷）。`fix2` 只表示
> "同一版本下的第几轮修复"——已被后续 fix 包取代为历史验证包；**当前验证请装最新 fix 包**。

### 修复（按你的反馈逐条）

- **滚动日志时画面跳动、不是滚到顶而是"传送一段距离"**：两个成因都修了——①自动滚动默认开着，
  每 200ms 把你拽回去一点（现在点击「回到底部」会先接管正在进行的滑动惯性，设置也更听话）；
  ②日志超 1500 行后，每来一批新行会从顶部裁掉旧行，但滚动位置没跟着补偿（内容整体上移了
  一段）——现在按裁掉的行数精确回补滚动位置。**关掉自动滚动开关也躲不掉的那个"传送"就是②修的**。
- **「回到底部」按钮点了没到底**：你的滑动惯性（甩动）还在飞时点它，会被惯性夺回去——
  现在点它会先接管惯性，再一钉到底（并复检一次）。
- **日志页帧率低**：过滤与染色的热路径做了早退优化；完整重构（增量渲染）排进批 C。
- **点「用外部浏览器打开」后，App 停在原来的界面**：现在会**退回首页（实例列表）**，
  dsh 页面收尾退出（不再残留、不再白屏）。
- **用外部浏览器打开后显示 `dsh web authentication required`**：根因查明——叠着的旧弹窗
  带着**已失效的旧 token**（dsh 重启后 token 会变）且外部浏览器没有登录 cookie。现在
  ①弹窗加了守卫不再叠影、②外跳时用**点击那一刻的最新 URL**——两处一起修掉。
- **点「仍要继续」后警告框不消失、背景已在加载 dsh**：弹窗会叠加（5 秒能叠 4 个），
  点掉一个下面还压着旧的。现在同一时刻最多一个弹窗，点掉就干净消失，且"继续"只放行一次。

## 0.1.6-SNAPSHOT

> **这是给真机首验的包（对照基准）**。当前验证包是 **fix2**——不要装本包，除非做对照测试。
> 本版只做一件事：**让 App 在真机上第一次真正跑通**
> —— 装上 → 装 dsh → 启动 → 在界面里对话 → 停止 → **再次启动不再报端口被占**。
> 界面结构、按钮位置与 0.1.5 完全一样；改的全是"让第一步能走通"的底层问题。

### 修复

- **「停止」以后 dsh 其实没停干净 → 下次启动报端口被占（`EADDRINUSE`）**。
  上一版让你"能起来一次"，但停不彻底。根因是**停止信号发给了错误的进程**：真正在跑的
  dsh 是 Linux 子进程，而旧代码把信号发给了外层的"翻译器"，那个进程**故意忽略**了它。
  现在改成用**该翻译器唯一会响应**的信号，让它带走整棵子进程树。
- **取消安装 / 安装超时后，后台的下载进程杀不掉**（同一个根因，安装路径也一并修了）。
- **「停止」后马上「启动」有时新旧两个进程会抢同一个端口**。现在启动前会**等上一个真正退干净**再起。
- **手动设的端口会被自动换掉后永久覆盖**。现在只有你没固定端口时才自动分配。
- **少数日志会丢**：日志刷新正好和写入撞上时，那几行可能既不显示也不落盘。已修。

### 变更

- **首次运行环境的解压期间会保持 CPU 唤醒**：解压要几分钟，以前手机灭屏可能把它掐断/挂起，
  现在解压期间不让系统睡着，解压一结束立即放开（不影响平时耗电）。
- **磁盘空间要求算准了**：旧版按"瘦身前"的旧数字算，会把本来够用的手机误判成"空间不足"。
  现在按实际大小：首次安装约需 **1.4GB** 空闲，升级约 **862MB**。
- **安装自检、DNS 就绪判断、脚本交互**三处脚本层面的小问题修掉（自检更少误报、安装更少卡住）。

### 升级须知

- 这版**专为验证端到端流程**，装上后请用应用内「设置 → 运行时自检」
  把「装 → 启 → 对话 → 停 → 再启」走一遍。任何一步失败，请把日志（应用内日志页 /
  `logs/runtime.log`）原样记下来反馈。
- 实例数据、配置**不受影响**，就地升级即可。

### 新增

- **任务区现在会说"结果"**：以前只显示"正在进行"，取消或失败之后那一行**瞬间消失**，
  用户看不到发生了什么。现在完成 / 失败 / 已取消都会留在列表里（保留最近 20 条），
  失败会带上原因；取消与停止也换成了两张不同的图标（原来长得一样）。
- **首次进界面时会提示去哪填 API Key** —— 只提示一次，之后不再打扰。

### 变更

- **API Key 完全由 dsh 自己管**：启动器不再保存、不再注入、也不再在启动前检查。
  - 表现上的变化：**没配 Key 也能启动**（以前会弹一个"尚未配置 API Key"的框挡住），
    起不来的是对话而不是整个实例。填 Key 的位置在 **dsh 界面里 → 设置 → 模型**。
  - **为什么必须这么改**：dsh 把"从启动环境继承来的 Key"视为最高优先级且**只读**，
    一旦启动器注进去，你在 dsh 的模型页里改 Key 会**直接被拒绝**（报错），
    等于在 App 里无论如何都改不掉。所以这不是取舍，是必须去掉。
- **实例详情里的"模型"设置行去掉了**：查证后确认那一项**从来没生效过** ——
  它对应的是一个并不被 dsh 读取的环境变量（同名常量在 dsh 里是另一个东西）。
  模型请到 **dsh 界面 → 设置 → 模型** 里选。
- **界面皮肤按 FCL 原版逐个对齐**（这一项看起来琐碎，但"塑料感"基本都来自它）：
  - **实例卡片在暗色下不再发白**（`auto_tint` 挂在错误的控件类上，一直静默失效）；
  - **图标不再全是默认黑色**（着色只对背景生效，以前挂在 `src` 上等于没上色）；
  - **切换亮暗主题后，已显示的行不再停在旧配色上**；
  - 日志页不再用自创的深色终端配色，改用与主题配套的一套，亮暗各一份；
  - 一票尺寸/留白/层级的对齐：页面左右留白、右面板内边距与标题字号、设置行的点击反馈、
    开关行高、组标题弱化、版本行的安装按钮改图标、任务区与其它列表统一。

### 修复

- **取消安装后"安装中"再也不消失**（要重启 App 才恢复）：取消时没有发出"结束"信号，
  界面永远等不到。现在取消有明确终态，且不会再闪一下"安装失败"。
- **"停止"可能停掉另一个实例**：任务行的停止动作没校验归属，从渲染到点击之间状态一变就停错。
- **运行时准备失败几乎看不到原因**（只在极短的竞态窗口里闪一帧）—— 现在会留在任务区。
- **安装失败记录无限增长**（内存缓慢泄漏）—— 失败后也做一次清理，原因不会丢。
- **安装失败时会告诉你真正的原因了**：以前不管什么原因，界面上只有一句
  「安装失败（详见日志）」。原因是**认不出新版本 npm 的报错格式**

### 修复

- **停止实例后 dsh 进程残留**：以前"停止"之后 rootfs 里的 dsh 进程可能还活着、继续占着端口，
  于是**下一次启动报 `EADDRINUSE`**（同一个实例第二次起不来）。本版从三个方向一起修：
  - 启动脚本把 dsh 进程的真实 pid 写出来，停止时**按 pid 精确终止**；
  - 停止信号换成 dsh 底座真正会响应的那个（以前发的信号它直接忽略，实际是靠强杀收尾，
    而强杀来不及清理子进程 —— 这才是残留的根因）；
  - 万一端口还是被占，**自动改用系统分配的端口**并写进日志，而不是丢一句"启动失败"。
- **"无法取得进程 pid"**：这条警告让"App 被杀之后仍在跑的实例"无法被识别和清理。
  根因是取值方式在 Android 上根本不成立（用了一个 Android 运行时不提供的方法）。
  现在补了一条从系统进程表读取的兜底路径。
- **首启准备页按返回会直接退出 App**：准备页是从启动画面直接进来的，任务栈里只有它自己，
  按返回等于把 App 关掉（用户以为崩了）。现在按返回是**回到桌面**，任务和正在跑的解压都留着，
  从最近任务点回来还能接着看。
- **从外壳进准备页再返回会叠出第二个主界面**：现在复用已有的主界面实例，不再新建。

### 升级须知

- **实例数据（名称、配置、已装版本）不会丢**，就地升级即可。
- 如果你曾经因为"停止后残留"而遇到过启动失败：**这一版修好了**，
  但建议升级后先重启一次手机（清掉之前残留的进程），再启动实例。
