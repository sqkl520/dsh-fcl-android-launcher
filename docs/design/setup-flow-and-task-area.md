> 依据：真机反馈「前置都放在第一次启动时，用一次性卡片页装好再进首页」与
> 「首页改成进行中任务的显示区域，所有正在运行的任务都必须显示，按 FCL 的 UI 来」。
> 样式全部用现有 FCL 件：FCLConstraintLayout / bg_container_white / bg_item_rounded /
> FCLProgressBar / FCLButton / FCLTextView / FCLImageView。
>

## 一、首启前置页（一次性）

### 何时出现
`DshBootstrap.isReady() == false` 且**本机从未完成过一次准备**（持久化标记判断）。

- 之前：首页挂一条横幅，点「准备运行时」才开跑，横幅文案还会被「未就绪 / 失败」互相覆盖
- 之后：首次启动直接进这一页，准备完成前不进首页；完成后写标记，以后再启动直接进首页

### 正常进行中

```
+-------------------------------------------------------------------+
|  DSHarness-FCL-Launcher                                     v0.1.0 |
|                                                                   |
|  +-------------------------------------------------------------+  |
|  |  正在准备运行环境                                           |  |
|  |  ---------------------------------------------------------- |  |
|  |  当前步骤：解压 Linux 运行时（rootfs）                      |  |
|  |  ############--------------------  38%                      |  |
|  |  正在解压：usr/lib/aarch64-linux-gnu/libabsl_status...      |  |
|  |  预计剩余：约 2 分钟                                        |  |
|  +-------------------------------------------------------------+  |
|                                                                   |
|  +- 准备项 -----------------------------------------------------+  |
|  |  [v] proot 运行时        已就绪（jniLibs，无需解压）        |  |
|  |  [v] 启动脚本            已解压                             |  |
|  |  [>] Linux rootfs        解压中 - 38%                       |  |
|  |  [ ] 运行时自检          等待中                             |  |
|  +-------------------------------------------------------------+  |
|                                                                   |
|  [ 查看日志 ]                                        [ 重新开始 ] |
+-------------------------------------------------------------------+
```

### 失败

```
|  +-------------------------------------------------------------+  |
|  |  ! 准备失败                                                 |  |
|  |  原因：可用空间不足：需要约 2.2 GB，当前 1.1 GB              |  |
|  |  （或：proot 执行失败（退出码 1）：/bin/sh: not found）      |  |
|  |                                                             |  |
|  |  [ 查看日志 ]                                    [ 重试 ]   |  |
|  +-------------------------------------------------------------+  |
|   失败时**停在本页**，不自动进首页，也不弹窗（原因就写在卡片里）  |
```

### 要点
- 进度、当前步骤、明细**各有固定位置**（不再像横幅那样被其它文案覆盖）
- 失败**停在本页**并显示真实原因 + 「重试」「查看日志」
- 成功后自动进首页，并持久化「已完成」标记
- 「重新开始」= 清掉 version 标记重解压（解决「卡在半成品」的恢复问题）

## 二、首页任务区

### 位置
放在实例列表**上方**、页面顶部（原「底座状态横幅」的位置）。**无任务时整块隐藏**。

样式照 FCL 的 `item_download_task.xml`：标题（12sp，主题色）+ 3dp 进度条 + 右侧 28dp 图标按钮。

```
+- 进行中 ------------------------------------------------------+
|  dsh 0.2.1-alpha.1 - 安装中...                           [ x ] |
|  ###################---------------------------  46%           |
+---------------------------------------------------------------+
|  准备运行环境 - 解压 Linux rootfs                        [ x ] |
|  ##########------------------------------------  21%           |
+---------------------------------------------------------------+
   [ 实例列表 / 空态提示 ... ]
```

### 覆盖哪些任务
| 任务 | 来源 | 进度 | 可取消 |
|---|---|---|---|
| 解压运行环境 / 自检 | `DshBootstrap.progress` | 分阶段 + 明细 | 建议不可取消（避免半成品） |
| 安装 dsh（每实例） | `DshInstaller.progress` + `statuses` | npm 输出 → 百分比 | 可取消（已有 cancel 能力） |
| 启动 dsh | `DshRuntime.state` | 无百分比 → 不确定进度条 | 可停止 |
| 删除实例 | `DshInstances.deleting` | 无百分比 | 不可取消 |

### 要点
- **所有进行中任务都在这里**，不再需要在每个页面各自显示（下载页只保留「安装中」角标）
- 全部完成/取消后整块自动消失
- 与「首启前置页」的分工：**前置页只管「运行环境」这一类**；日常的安装/启动/删除任务走首页任务区

## 三、需要确认的 3 个点

1. **首页那块旧的「底座状态横幅」要不要删掉？**
   建议：**删**。它的职责被「首启前置页（未就绪时）+ 首页任务区（进行中时）」完全覆盖，
   留着就是两处显示同一件事（而现在横幅还有「失败原因被覆盖」的 bug）。
2. **首启前置页允不允许「跳过」？**
   建议：**不提供跳过**（没有底座，dsh 装不了也起不来），但失败时给「重试」「查看日志」。
3. **前置页要不要「准备项清单」那块？**
   建议：**要**（用户能看懂卡在哪一步），但它占地方 —— 若嫌啰嗦可以只留进度卡片。
